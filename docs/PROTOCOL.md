# Mod ↔ page protocol (v1)

Transport: WebView2 web messages. JavaScript posts **strings** with
`window.chrome.webview.postMessage(...)`; the mod reads them with
`TryGetWebMessageAsString` and answers with `PostWebMessageAsString`. No JSON is
parsed on the C++ side; every message is a single string whose fields are
separated by `U+001F` (unit separator, `\x1f`). The **last field may contain
`\x1f`** (HTTP bodies, settings JSON), so parsers must split with a field limit,
never greedily.

First field is always the protocol tag `whtr1`, second the message kind.

## Page → mod

### `http` — perform one HTTP request

```
whtr1 \x1f http \x1f <requestId> \x1f <method> \x1f <url> \x1f <headerCount> \x1f
<name1> \x1f <value1> \x1f ... \x1f <nameN> \x1f <valueN> \x1f <body>
```

* `requestId`: positive integer, unique per page instance; the reply echoes it.
* `method`: `GET` or `POST` (anything else → error reply).
* `url`: absolute `https://` or `http://`, length ≤ 4096.
* `headerCount`: 0..32. Headers whose name or value contains `\x1f` are rejected.
* `body`: UTF-8; empty string for `GET`. Length ≤ 1 MiB.

### `settings?` — ask for the current settings

```
whtr1 \x1f settings?
```

### `log` — write one line to `p0.log`

```
whtr1 \x1f log \x1f <text>          (text ≤ 500 chars, no reply)
```

## Mod → page

### `http` reply

```
whtr1 \x1f http \x1f <requestId> \x1f <status> \x1f <error> \x1f <body>
```

* `status`: HTTP status code, or `0` when the request never completed.
* `error`: `0` on success, otherwise a Win32/WinHTTP error code in decimal.
* `body`: response body as UTF-8 text (empty on error). Truncated at 1 MiB.

### `settings` — pushed at page start (`ready`) and on every settings change

```
whtr1 \x1f settings \x1f <json>
```

The JSON object is generated by the mod and contains exactly the keys below
(all values strings, numbers or booleans):

| key | type | meaning |
| --- | --- | --- |
| `targetLang` | string | `auto` or a BCP-47 tag |
| `provider` | string | `auto` \| `edge` \| `google` \| `llm` |
| `llmBaseUrl` / `llmModel` | string | OpenAI-compatible endpoint and model |
| `llmKeySource` | string | `credential` \| `setting` \| `none` |
| `scopeReadme` / `scopeSettings` / `scopeList` / `scopeChangelog` | boolean | per-surface switches |
| `hoverDelayMs` | number | 0..2000 |
| `shortcutToggle` / `shortcutMode` | string | e.g. `Alt+Q`, empty to disable |
| `batchSize` / `batchChars` / `batchIntervalMs` / `concurrency` / `timeoutMs` | number | request tuning |
| `cacheEnabled` | boolean | |
| `cacheTtlDays` | number | |
| `clearCache` | boolean | true once when the user asks for it; the mod resets the setting after pushing |
| `debug` | boolean | verbose JS logging through `log` |

The API key is **never** part of this payload. When `llmKeySource` is not `none`
the mod adds the `Authorization` header itself for requests whose URL matches
`llmBaseUrl`'s host, i.e. the page sends the request without the key and the mod
injects it.

## Rules

* Unknown kinds, malformed messages and oversized payloads are ignored with one
  log line; they never throw across the COM boundary.
* Every reply must be sent on the WebView2 UI thread.
* The page is free to send `settings?` again at any time; replies are idempotent.
* One page instance may have several requests in flight; `requestId` correlates.
